# Personal Finance ETL — v9.1.0 Semantic Hardening Plan

> **Theme:** Make every important boundary explicit.  
> **Baseline:** v9.0.1  
> **Scope:** semantic typing, source documentation, public contracts, and justified typing exceptions.  
> **Out of scope:** major workflow decomposition, performance tuning, finance features, ML/AI, and financial-semantic changes.

## Release objective

v9.0.1 put code in the correct architectural home. v9.1.0 makes the code inside those homes self-describing.

```text
v9.0.1
Where does this code belong?
        ↓
v9.1.0
What exactly crosses this boundary,
what does it mean, and what can fail?
```

## Evidence from v9.0.1

- 277 `Any`-bearing lines across 55 files.
- 147 `dict`/`Mapping` structures involving `Any` across 37 files.
- Domain + application contain 224 of the 277 `Any` lines.
- 59 public functions, 37 public classes, and 46 public methods lack docstrings.
- All 156 production modules already have module docstrings.
- 38 of 42 package `__init__.py` files already expose `__all__`.
- Only 12 `type: ignore` annotations remain, mostly third-party/library typing gaps.

The release therefore targets **semantic boundaries**, not package architecture.

# Phase 1 — Establish the semantic baseline

## Goal
Classify before changing.

Create a working inventory of every remaining `Any`, mapping containing `Any`, dynamic callable, and `type: ignore`.

Classify each as:

```text
REPLACE_WITH_EXISTING_CONTRACT
CREATE_NAMED_CONTRACT
NARROW_TO_UNION
NARROW_TO_OBJECT
THIRD_PARTY_TYPING_GAP
SERIALIZATION_BOUNDARY
GENUINELY_HETEROGENEOUS
NUMBA_OR_LIBRARY_LIMITATION
```

Priority: `isin_service.py` → investment contracts → input adapters → remaining domain/application mappings → infrastructure boundaries.

**Exit:** every occurrence has a disposition; no blind global replacement.

# Phase 2 — Finish investment and application contracts

## Goal
Remove the highest-value anonymous financial structures first.

Focus on instrument purchase/sale records, market state, master metadata, realized/reconciliation events, cash flows, terminal values, snapshots, ISIN results, and aggregation results.

Prefer extending the existing investment contract model over parallel DTO families.

**Do not decompose the 655-line workflow yet.** Type the boundary first; simplify it in v9.2.0.

**Exit:** major Quant/application boundaries no longer require undocumented dictionary keys.

# Phase 3 — Harden remaining domain and application typing

Review household/wealth mappings, Tax structures, worker/status callbacks, façade dependencies, calculation results, and lifecycle/recovery messages.

Use `object` when unknown values must be narrowed before use. Use unions/value objects when legal states are known.

**Exit:** stable domain/application contracts contain no unexplained `Any`.

# Phase 4 — Infrastructure and external typing boundaries

Review provider payloads, filesystem/preferences serialization, Control Plane error/serialization context, yfinance/customtkinter/markdown boundaries, Polars gaps, and Numba gaps.

For every surviving exception record location, reason, category, narrowing point, and removal condition if any.

**Exit:** every remaining `Any` and `type: ignore` has an architectural reason.

# Phase 5 — Complete source documentation protocol

Use one repository-wide docstring style. NumPy style is recommended.

Every public class documents purpose, responsibilities, state/invariants, important dependencies, and lifecycle where relevant.

Every public function/method documents purpose plus Parameters, Returns, Raises, Side Effects, financial grain/semantics, and invariants where relevant.

Private callables are documented when non-trivial, financial, stateful, algorithmically complex, or performance-sensitive.

Priority: Quant public methods → FinancialRules models → ingestion/providers → domain calculators/builders → remaining public callables → meaningful private algorithms.

**Exit:** no undocumented production public class/function/method and no important private algorithm lacking necessary explanation.

# Phase 6 — Public API and semantic certification

Review all 42 package `__init__.py` files, the four without `__all__`, deep imports, duplicate/legacy aliases, accidental exports, and exception/result/status consistency.

Run strict mypy, strict Pyright, Ruff, architecture tests, phase regression tests, and a real end-to-end pipeline.

Compare financial outputs with v9.0.1.

## v9.1.0 Definition of Done

- stable domain/application structures are named and semantically typed;
- every surviving `Any` is justified;
- typing exceptions are registered;
- source documentation protocol is complete;
- public package surfaces are intentional;
- financial outputs and behavior are unchanged;
- contracts are frozen for v9.2.0.

> **Outcome:** the code explains what it means before you read how it works.
