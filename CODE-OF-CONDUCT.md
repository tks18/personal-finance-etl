# Code of Conduct

## Purpose

Personal Finance ETL is a personal open-source project built around finance, data engineering, analytics, and software architecture.

I welcome thoughtful discussion, bug reports, ideas, documentation improvements, and contributions that help make the project more reliable, understandable, and useful.

The expectation is simple:

> **Be respectful, constructive, and focused on improving the project.**

---

## Expected Behaviour

When participating in this project:

- Treat other contributors and users with respect.
- Discuss ideas, implementations, and trade-offs rather than attacking people.
- Give technical feedback clearly and constructively.
- Assume good intent while still questioning assumptions and code.
- Be patient with different levels of experience.
- Keep issues and pull requests relevant to the project.
- Respect privacy, especially when discussing financial data or examples.
- Clearly identify assumptions, limitations, and uncertainty when discussing financial behaviour.

Healthy disagreement is welcome.

Personal hostility is not.

---

## Financial Discussions

This project deals with personal finance, investments, tax-oriented analytics, and financial planning.

Contributors should distinguish between:

```text
financial modelling
planning guidance
software behaviour
```

and:

```text
personal financial advice
tax filing advice
legal advice
```

When proposing financial logic, explain the assumptions and reasoning behind it.

Do not present modelled outputs or project behaviour as universally applicable financial, tax, or legal advice.

---

## Privacy and Financial Data

Do not post sensitive personal or financial information in public issues, discussions, logs, screenshots, test fixtures, or pull requests.

Examples include:

- account numbers;
- personally identifiable financial records;
- broker statements containing private information;
- tax identifiers;
- credentials or API secrets;
- private database contents.

Use synthetic or anonymized examples whenever possible.

If sensitive information is accidentally exposed, remove it from the discussion or contribution as quickly as possible and notify the maintainer.

---

## Contributions

Contributions should aim to preserve the project's core principles:

```text
local-first
financially explainable
configuration-driven
reproducible
observable
reliable
evidence-aware
```

A contribution does not need to be large to be valuable.

Bug fixes, tests, documentation corrections, clearer error messages, performance improvements, and small reliability improvements are all welcome.

When proposing substantial changes, explain:

1. What problem exists.
2. Why the change is useful.
3. How the proposed solution addresses it.
4. What financial or technical behaviour may change.
5. How the change can be verified.

Prefer solving real problems over adding complexity for its own sake.

---

## Unacceptable Behaviour

The following are not acceptable:

- harassment, threats, or personal attacks;
- discriminatory or demeaning language;
- deliberate disruption of project discussions;
- publishing another person's private information;
- knowingly submitting malicious code;
- intentionally misleading users about financial behaviour;
- presenting uncertain financial assumptions as guaranteed facts;
- repeatedly ignoring reasonable maintainer guidance.

---

## Enforcement

As the project maintainer, I may edit, remove, reject, or close contributions and discussions that violate this Code of Conduct or materially disrupt the project.

Depending on the situation, this may include:

```text
requesting a correction
removing inappropriate content
closing an issue or pull request
rejecting a contribution
restricting further participation
```

Enforcement decisions will focus on maintaining a respectful, technically useful project environment.

---

## Reporting a Problem

If you encounter conduct that should not be handled publicly, contact me privately through an appropriate contact method listed on my GitHub profile rather than posting sensitive details in a public issue.

Please include enough context for me to understand what happened while avoiding unnecessary disclosure of private information.

---

## Scope

This Code of Conduct applies to participation in the project's GitHub repositories and other project-managed community spaces.

It is intended to keep collaboration productive without turning a personal open-source project into a bureaucracy.

---

## Final Principle

Good engineering depends on being able to challenge ideas without attacking people.

Be curious.

Be precise.

Be respectful.

And leave the project better than you found it.
